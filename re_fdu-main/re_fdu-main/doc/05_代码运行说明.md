# 05 · 代码运行说明

> 本文档说明如何在本地启动 RE:FUDAN（复见）Agent Demo。预计耗时 10-15 分钟（含 SecondMe 应用注册）。

## 1. 环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| **Bun** | ≥ 1.3 | 项目包管理 + 脚本执行 |
| **Node.js** | ≥ 20 | 部分原生模块兼容 |
| **Git** | ≥ 2.30 | 拉取代码 |
| **浏览器** | Chrome / Edge 最新版 | 演示与 SecondMe 授权 |

### 安装 Bun

| 系统 | 命令 |
|---|---|
| Windows (PowerShell) | `irm bun.sh/install.ps1 \| iex` |
| macOS / Linux | `curl -fsSL https://bun.sh/install \| bash` |

## 2. 获取代码

```bash
git clone https://github.com/fishine-cmd/REFUDAN.git
cd REFUDAN/re_fdu-main/re_fdu-main
```

> 注意：当前仓库结构是双层嵌套 `re_fdu-main/re_fdu-main/`——实际代码在内层目录。后续会扁平化。

## 3. 安装依赖

```bash
bun install
```

预计 6-10 秒完成（首次需要下载 200+ 包，耗时较长）。

## 4. 配置环境变量

### 4.1 复制示例文件

```bash
cp apps/site/.env.example apps/site/.env.local
```

### 4.2 注册 SecondMe OAuth2 应用

1. 浏览器打开 https://develop.second-me.cn/integrations/list
2. 用你的 SecondMe 账号登录（如无账号，先去 https://second.me 注册）
3. 点击「新建应用」，按以下字段填写：

| 字段 | 值 |
|---|---|
| 应用名称 | `RE:FUDAN` 或自定义 |
| 应用类型 | Web 应用 |
| 回调 URL（Redirect URI） | `http://localhost:3000/api/auth/secondme/callback` |
| 权限范围（Scopes） | 勾选 `userinfo` + `chat.write` + `memory.read` |
| Webhook URL | 留空（本地演示不需要） |

4. 提交后**立即复制** Client ID 和 Client Secret（Secret 只显示一次）

### 4.3 填写 `.env.local`

打开 `apps/site/.env.local`，把刚才拿到的两个值粘贴进去：

```env
SECONDME_BASE_URL=https://api.mindverse.com/gate/lab
SECONDME_AUTH_URL=https://go.second-me.cn/oauth/
SECONDME_CLIENT_ID=你刚才复制的 Client ID
SECONDME_CLIENT_SECRET=你刚才复制的 Client Secret
SECONDME_REDIRECT_URI=http://localhost:3000/api/auth/secondme/callback
SECONDME_SCOPES=userinfo,chat.write,memory.read

# 可选：兜底 LLM（未授权 mentor 才会用到，不填也能演示）
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
```

## 5. 启动开发服务器

### 主演示应用（端口 3000）

```bash
cd apps/site
bun run dev
```

控制台显示：
```
   ▲ Next.js 15.5.18
   - Local:        http://localhost:3000
 ✓ Ready in 2.5s
```

浏览器访问 http://localhost:3000 即可看到落地页。

### （可选）架构示意应用（端口 3001）

```bash
cd apps/app
bun run dev
```

> `apps/app` 是 P0-P4 静态架构示意，与产品主流程独立。**完整 demo 仅看 `apps/site` 即可**。

## 6. 演示路径

| 步骤 | URL | 说明 |
|---|---|---|
| 1 | http://localhost:3000 | 落地页，"复见"理念 |
| 2 | http://localhost:3000/mentor-onboard | 学长授权管理：选一位 mentor 点「开始 SecondMe 授权」 |
| 3 | (跳转 second.me) | 用你的账号登录并同意授权 |
| 4 | 自动回到 `/mentor-onboard?status=success` | 看到绿色 banner + 该卡片"SecondMe 分身已接入" |
| 5 | http://localhost:3000/mentors | 学弟妹视角，6 位 mentor 雷达图列表 |
| 6 | 任选一位 mentor → "让我的 Agent 去聊聊" | 进入 `/agent-workbench` |
| 7 | 选 `match` 区，对话框输入问题 | 已授权的 mentor → SecondMe 流式回复；未授权的 → 兜底回复 |
| 8 | 返回 `/mentor-onboard` 点「撤销授权」 | 演示数据撤回；卡片回到"待绑定"状态 |

## 7. 验证安装成功

发出第一条对话后，dev server 终端应该输出类似：
```
[secondme] chat/stream status: 200 content-type: text/event-stream; charset=utf-8
[secondme] chunks emitted: 59
 POST /api/chat 200 in 9337ms
```

`chunks emitted > 0` 说明 SecondMe 真分身正常返回流式回复。

```bash
cd packages/contracts && bun run typecheck
```

三个都应该静默通过（无任何 error）。

## 9. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 点"开始授权"后页面显示 `{"detail":"Not Found"}` | `SECONDME_AUTH_URL` 配错 | 确认是 `https://go.second-me.cn/oauth/`（末尾有 `/`） |
| 授权回调失败 banner 显示 "redirect_uri 不匹配" | 控制台填写的回调地址和 `.env.local` 不一致 | 严格对齐到 `http://localhost:3000/api/auth/secondme/callback` |
| 对话提示"SecondMe 分身未返回内容" | 分身资料完整度过低（profileCompleteness < 30） | 去 second.me 给分身补充自我介绍 / 经验笔记 |
| 对话提示"网络异常" | 通常是 dev server 没有热重载到最新代码 | `Ctrl+C` 重启 `bun run dev` |
| typecheck 报 mentor JSON 缺字段 | git pull 后部分 mentor 没有 consent 字段 | 删除 `mentor_tokens.json` 重新跑授权流程 |
