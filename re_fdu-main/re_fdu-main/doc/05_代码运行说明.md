# 05_代码运行说明

> 本文对应训练营中期材料中的“代码运行说明”。  
> 目标是帮助评审或助教快速理解依赖关系，并尽可能复现当前核心 Demo。

## 1. 项目运行概览

当前 RE:FUDAN 工作版主要由三部分组成：

1. `apps/site`
   - 主站
   - 包含页面、API、推荐逻辑、A2A 会话逻辑、登录注册逻辑
2. `packages/contracts`
   - 前后端共享类型
3. `services/profile-extraction`
   - Python 画像抽取与分析流水线

如果只想跑通“主站页面 + 推荐 + A2A 自动多轮”，至少需要：

- Bun
- Node.js
- Upstash Redis
- DeepSeek API Key

如果还想跑通“生成 Agent 档案”，还需要：

- Python
- `services/profile-extraction` 依赖

## 2. 环境要求

| 组件 | 建议版本 | 是否必需 | 作用 |
| --- | --- | --- | --- |
| Bun | `>=1.3` | 是 | 安装依赖、运行主站 |
| Node.js | `>=20` | 是 | Next.js runtime |
| Python | `3.11` 或 `3.12` | 画像功能必需 | 运行画像流水线 |
| Git | 较新版本 | 建议 | 拉取仓库 |

## 5. 配置环境变量

### 5.1 复制模板

```bash
cp apps/site/.env.example apps/site/.env.local
```

Windows PowerShell 也可以手动复制该文件。

### 5.2 当前最关键的环境变量

打开 `apps/site/.env.local`，至少补齐：

```env
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
DEEPSEEK_API_KEY=
```

建议保留：

```env
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
```

### 5.3 可选环境变量

当前模板中仍保留：

```env
SECONDME_BASE_URL=https://api.mindverse.com/gate/lab
SECONDME_AUTH_URL=https://go.second-me.cn/oauth/
SECONDME_CLIENT_ID=
SECONDME_CLIENT_SECRET=
SECONDME_REDIRECT_URI=http://localhost:3000/api/auth/secondme/callback
SECONDME_SCOPES=userinfo,chat.write,memory.read
```

说明：

- 这组变量主要用于后续能力扩展
- 当前中期演示主链路不依赖它们才能跑通

## 6. 云端依赖说明

### 6.1 Upstash Redis

Redis 当前承载：

- 用户信息
- 登录 session
- 学长 / 学弟索引
- 推荐缓存
- A2A session metadata
- A2A turn / trace / assessment
- handoff / referral 状态

如果 Redis 未配置：

- 登录注册不可用
- 推荐页不可用
- 会话中心不可用

### 6.2 DeepSeek API

DeepSeek 当前用于：

- 学长 Agent 回复生成
- autoplay 自动多轮中的 senior-side 回复
- 会话摘要与 handoff brief 的基础内容

如果 Key 未配置：

- 页面可以打开
- 但 A2A 生成会失败

如果 DeepSeek 临时不可达：

- 系统可能显示 fallback reply
- A2A 会尽量降级继续，但质量会下降

## 7. 初始化 demo 学长数据

主站当前依赖 Redis 中已有 demo 学长数据。

在 `apps/site` 目录执行：

```bash
cd apps/site
bun run seed
```

作用：

- 将 `src/data/mentors/*.json` 写入 Redis
- 自动创建 6 位 demo 学长账号
- 默认密码统一为 `demo123`

## 8. 启动主站

在 `apps/site` 下执行：

```bash
cd apps/site
bun run dev
```

默认访问地址：

```text
http://localhost:3000
```

调用入口：

## 11. 推荐运行验证顺序

为了减少排错时间，建议按以下顺序验证。

### 第一步：验证主站能打开

访问：

- `/`
- `/signup`
- `/login`

### 第二步：验证 Redis 读写正常

执行：

```bash
cd apps/site
bun run seed
```

然后：

- 使用 demo 学长账号登录
- 检查是否能进入 `/me/senior`

### 第三步：验证推荐与 A2A 自动多轮主链路

使用学弟账号：

1. 进入 `Agent 工作台`
2. 构建档案，或至少完成必要基础信息
3. 进入 `/me/junior`
4. 选择一个问题方向
5. 在推荐卡片中输入第一句问题
6. 启动 A2A 自动多轮
7. 检查是否出现：
   - 自动推进状态
   - summary / verdict / adjustedScore
   - “查看完整 A2A”入口

### 第四步：验证 P3 和 handoff

1. 进入 `/a2a/[sessionId]`
2. 检查自动轨迹是否存在
3. 切换到学长账号
4. 在 `/me/senior` 查看接力收件台
5. 完成 handoff 审批

### 第五步：验证 Python 画像流水线

在工作台中：

1. 输入 GitHub 用户名或其他社媒账号
2. 点击“生成我的 Agent”
3. 检查是否返回结构化档案

## 14. 常见问题

### 问题 1：主站能打开，但登录注册报错

大概率原因：

- Redis 未配置
- `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` 缺失

### 问题 2：A2A 只回一轮就停住

请优先检查：

- 是否在 `/me/junior` 或已经兼容后的 `agent-workbench` 路径触发
- 浏览器是否成功调用 `/api/a2a/sessions/[sessionId]/autoplay`
- Redis 中 session metadata 是否写入了 `autoplayState`

### 问题 3：前端显示 fallback reply

大概率原因：

- DeepSeek 网络请求失败
- 模型提供方暂时不可用

此时系统可能继续运行，但会使用保底回复。

### 问题 4：点击“生成我的 Agent 档案”失败

大概率原因：

- Python 未安装
- 虚拟环境依赖未安装
- 外部采集源访问失败
