# 03_demo视频说明

> 本文可直接作为中期材料中的“Demo 视频说明”。  
> 推荐视频时长：3 到 5 分钟。

## 1. 视频目标

这次 Demo 不需要覆盖仓库里的所有功能，重点是让评审老师在较短时间内看清三件事：

1. 这个项目在解决什么问题
2. 当前系统已经做到什么程度
3. 当前版本最有辨识度的亮点是什么

建议围绕当前真实可运行主链路录制，不再使用早期已经废弃的叙事方式。

## 2. 推荐演示主线

建议采用“学弟侧发起 - 系统自动多轮预沟通 - 学长侧接力”的结构。

### 场景 A：首页与项目定位

建议时长：20 到 30 秒

建议展示：

- 首页
- 一句话定位
- 产品流程概念

建议口播：

- RE:FUDAN 是一个面向复旦校园经验咨询场景的 Agent-Native 社交 Demo
- 项目目标是把高摩擦的人脉咨询，改造成先由 Agent 预沟通、再由真人决定是否接力的流程

### 场景 B：学弟构建 Agent 档案

建议时长：30 到 50 秒

建议展示：

- 登录或注册学弟账号
- 进入 `Agent 工作台`
- 填写学校、专业、GPA、目标等基础信息
- 可选展示社媒账号输入
- 点击“生成我的 Agent”

建议口播：

- 这里不是普通表单，而是用户侧的 Agent 工作台
- 系统可调用 Python 画像流水线生成结构化档案
- 档案会直接作为后续推荐和 A2A 的输入

### 场景 C：进入需求匹配页并选择问题方向

建议时长：25 到 40 秒

建议展示：

- 进入 `/me/junior`
- 选择一个问题方向，例如“保研 / 夏令营策略”
- 补充一句更具体的问题
- 查看围绕当前方向重排后的学长推荐卡片

建议口播：

- 推荐不是静态列表，而是围绕当前问题方向动态重排
- 系统会为每位学长生成推荐理由和适合切入的问题

### 场景 D：在需求匹配页直接触发 A2A 自动多轮

建议时长：50 到 80 秒

这是本次 Demo 最重要的部分。

建议展示：

- 在推荐卡片内输入第一句问题
- 点击启动 A2A
- 展示运行状态、轮次推进或当前主题提示
- 等待自动多轮结束
- 展示最终 summary / verdict / adjustedScore / coveredSlots

建议口播：

- 当前版本把 A2A 主触发点前移到了需求匹配页
- 用户只需要输入第一句方向性问题，后续 2 到 6 轮由 Agent 自动推进
- 系统围绕 5 类关键槽位继续追问，不是写死台词
- 对话结束后会把结论回流到推荐卡片

### 场景 E：进入 P3 查看完整轨迹

建议时长：30 到 50 秒

建议展示：

- 点击“查看完整 A2A”
- 进入 `/a2a/[sessionId]`
- 展示自动追问、学长回复、assessment、covered slots、trace

建议口播：

- P3 会话中心保留完整自动轨迹
- 这里可以清楚区分“用户首问”和“后续 AI 自动追问”
- 也是后续人工继续追问和 handoff 判断的依据

### 场景 F：切换到学长侧处理接力

建议时长：40 到 60 秒

建议展示：

- 切换到学长账号
- 进入 `/me/senior`
- 查看接力收件台
- 打开对应会话
- 审批 handoff
- 跳转到 P4 连接简报页

建议口播：

- 学长侧的重点不是继续聊天，而是判断是否值得进入真人接力
- P4 页面把背景、摘要、状态推进单独整理出来，避免和 P3 混在一起

### 场景 G：总结当前完成度

建议时长：15 到 25 秒

建议口播：

- 当前版本已经跑通“画像 - 推荐 - 自动多轮 A2A - handoff - P4”主链路
- 后续会继续提升自动多轮质量、推荐解释性和工程稳定性

## 3. 本次 Demo 最值得强调的亮点

建议优先强调以下几点：

- 需求匹配页可以直接触发 A2A 自动多轮，而不是只跳转到单独聊天页
- 自动多轮会围绕关键信息槽推进，不是固定话术脚本
- 对话结果会回流成推荐结论，而不是停留在聊天本身
- P3 与 P4 的职责边界清晰
- 系统背后不是纯前端 mock，而是 Redis + DeepSeek + Python 流水线协同

## 4. 推荐录制顺序

推荐顺序如下：

1. 首页
2. 学弟登录 / 注册
3. Agent 工作台
4. `/me/junior` 需求匹配页
5. 推荐卡片内启动 A2A 自动多轮
6. P3 会话中心
7. 学长接力收件台
8. P4 连接简报页
9. 总结

## 5. 建议口播关键词

为了让评审更快抓住重点，建议明确说出以下关键词：

- Agent 工作台
- 需求匹配页
- A2A 自动多轮预沟通
- assessment 回流
- P3 会话中心
- handoff
- P4 连接简报
- Upstash Redis
- DeepSeek
- Python 画像流水线

## 6. 录制注意事项

- 不要在视频里展示 `.env.local`、API key、Redis token 等敏感信息
- 如果 Python 画像流水线执行较慢，可以提前生成好一个档案，再录结果页
- 如果 DeepSeek 当前不稳定，可以提前准备一个已完成的 A2A session 用于展示
- 若出现 fallback reply，也可以顺带说明系统具备降级能力，但不要让它破坏主线节奏
- 建议使用 1920x1080 录制
