## 1. 项目目标

**一句话**：让经验先抵达，答案再相见——通过 AI 数字分身，为复旦学弟妹与学长学姐之间搭建一条"低摩擦、可解释、有秩序"的经验传承通道。

### 1.1 我们要解决的问题

- 优秀学长学姐时间精力有限，**重复回答**相似的升学/求职问题；
- 学弟妹面临严重的**信息壁垒**，难以有效定位"真正能给到帮助的人"并提出**结构化问题**；
- 传统校友撮合平台**冷启动困难**、社交摩擦高、隐私边界模糊。

### 1.2 我们的产品理念

**「让经验先抵达」**——基于 SecondMe 数字分身的 A2A（Agent-to-Agent）前哨对话：
学弟妹的 Agent 先与学长学姐**本人授权**的分身完成一轮高质量对话 →
分身给出**有出处、有可信度**的结构化回答 →
若双方仍希望进一步沟通，再以真人引荐形式连接，由真人决定时间与隐私级别。

### 1.3 核心约束（项目灵魂）

| 约束 | 说明 |
|---|---|
| **本人授权** | 每位被建模的学长学姐**必须本人**在 SecondMe 完成分身训练，并通过 OAuth2 授权 RE:FUDAN 调用其分身。**不进行任何形式的第三方信息爬取**。 |
| **可撤销** | 学长可在任何时点撤销授权，本地 access token 立即清除，对话能力即时下线。 |
| **明确标识** | 所有 AI 回复带"**AI 助手代为表达，非本人直接发言**"提示，并在 mentor 卡片显示"SecondMe 分身已接入"徽章。 |
| **数据最小化** | OAuth2 仅申请 `userinfo` / `chat.write` / `memory.read` 三个 scope；不申请 `chat.read`、`note.write`、`agent_memory` 等更具侵入性的权限。 |

## 2. Agent Demo 功能

### 2.1 已交付的核心能力

| 模块 | 路径 | 能力 |
|---|---|---|
| **学长授权管理** | `/mentor-onboard` | 列出 6 位授权学长学姐，一键发起 SecondMe OAuth2 授权、查看授权状态、随时撤销 |
| **学弟妹浏览** | `/mentors` | 雷达图展示 mentor 匹配度（院校/专业/目标重合/经历相似），SecondMe 接入状态徽章 |
| **A2A 对话工作台** | `/agent-workbench` | 选中 mentor 发起对话，已授权者由本人 SecondMe 分身流式回复，未授权者由本地兜底模型基于授权问卷回复，回答顶部带合规水印 |
| **OAuth2 全链路** | `/api/auth/secondme/{authorize,callback,revoke,status}` | CSRF state 校验、code → token 交换、appScopedUserId 拉取、本地 token 落地、撤销 |
| **Chat 智能分发** | `/api/chat` | mentor 授权且已绑定 → SecondMe SSE 中转；否则 → 兜底 LLM 路径，保证演示稳定 |

### 2.2 用户旅程演示（5 步）

```
学长侧（mentor）                  学弟妹侧（mentee）
─────────────────                ──────────────────
1. /mentor-onboard
   "开始 SecondMe 授权"
       ↓ OAuth2 跳转
2. 在 SecondMe 同意授权
       ↓ 回调
3. 卡片变绿: "SecondMe 分身已接入"
                                  4. /mentors 看到 6 位学长
                                     雷达图 + 已接入徽章
                                        ↓
                                  5. /agent-workbench
                                     发问 → SecondMe 流式回复
                                        ↓
                                  6. 「真人引荐入口」（占位）
```

## 3. 系统设计

### 3.1 五层架构

```
┌──────────────────────────────────────────────────────────┐
│  L5  演示前端 (apps/site, Next.js App Router)             │
│   - /mentor-onboard   学长授权管理                          │
│   - /mentors          学弟妹浏览推荐                        │
│   - /agent-workbench  A2A 对话工作台                        │
└──────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────┐
│  L4  同意管理层                                            │
│   - mentor JSON.consent_status / consent_granted_at        │
│   - mentor_tokens.json (本地 OAuth2 token 持久化)          │
│   - /api/auth/secondme/{authorize,callback,revoke,status}  │
│   - 合规水印 + 撤回入口 + 状态徽章                          │
└──────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────┐
│  L3  Agent 编排层 (Next.js Route Handlers)                 │
│   /api/chat 智能分发：                                      │
│     ✓ consent_status=granted 且有 token → SecondMe 流式    │
│     ✓ 否则 → 兜底 LLM (system prompt + 授权问卷)            │
└──────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────┐
│  L2  SecondMe API 客户端 (src/lib/secondme.ts)             │
│   buildAuthorizeUrl / exchangeCodeForToken                 │
│   fetchUserInfo / streamChat (SSE parser)                  │
│   saveMentorToken / revokeMentorToken / refreshAccessToken │
└──────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────┐
│  L1  SecondMe 平台 (second.me)                             │
│   学长本人注册 + 上传记忆/笔记 + 训练分身 + 授权 RE:FUDAN    │
└──────────────────────────────────────────────────────────┘
```

### 3.2 OAuth2 授权码流程

```
   学长本人              RE:FUDAN apps/site             SecondMe 平台
       │                       │                              │
       │ ① 点击「开始授权」      │                              │
       ├──────────────────────→ │                              │
       │                       │ ② 生成 state + cookie         │
       │                       │ ③ 302 → authorize URL         │
       │ ←─────────────────────┤                              │
       │ ④ go.second-me.cn/oauth/ 同意                          │
       ├─────────────────────────────────────────────────────→│
       │                       │ ⑤ /callback?code=lba_ac_… &state│
       │ ←─────────────────────────────────────────────────────┤
       │                       │ ⑥ 校验 state CSRF              │
       │                       │ ⑦ POST /api/oauth/token/code    │
       │                       ├─────────────────────────────→ │
       │                       │ ⑧ {accessToken, refreshToken,  │
       │                       │    scope: [userinfo, chat.write,│
       │                       │           memory.read]}        │
       │                       │ ←─────────────────────────────│
       │                       │ ⑨ GET /api/auth/me             │
       │                       │   → appScopedUserId            │
       │                       │ ⑩ saveMentorToken(mentorId)    │
       │ ⑪ 跳回 onboard "已绑定"│                              │
       │ ←─────────────────────┤                              │
```

### 3.3 流式对话路径（验证已端到端打通）

```
浏览器 POST /api/chat
       ↓
/api/chat 分发:
  load mentor → consent_status="granted" && token 存在
       ↓
  await streamChat(token, message, onChunk):
    fetch POST https://api.mindverse.com/gate/lab/api/secondme/chat/stream
    ↓ SSE 流: text/event-stream
      data: {"choices":[{"delta":{"content":"..."}}]}    × N
      data: [DONE]
    ↓ 解析并累积 chunks
       ↓
  返回 { reply, source: "secondme", mentorId }
       ↓
浏览器渲染（陈晓远卡片下出现真分身回复）
```

> 验证记录：陈晓远 mentor 单条问题"你好，介绍一下自己" → SecondMe 实测返回 **59 个 chunk**，端到端耗时 9.3 秒，全链路成功。

## 5. 数据合规与伦理设计（项目灵魂）

我们对 SecondMe 平台的设计哲学进行了深度对齐——**"本人训练 + 本人授权 + 本人可撤回"**，并在以下五个维度落实合规：

| 维度 | 实现 |
|---|---|
| **来源合法** | 所有 mentor 资料来源于本人主动填写的经验问卷 + 本人 SecondMe 分身 OAuth2 授权调用；**不进行任何形式的公开社媒爬取或第三方数据采集**。 |
| **告知同意** | `consent_status` 字段记录授权状态，`consent_granted_at` 记录授权时点；mentor-onboard 页面对学长本人清楚展示授权范围（scope）。 |
| **数据最小化** | OAuth2 仅申请 `userinfo` + `chat.write` + `memory.read` 三个 scope；不申请 `chat.read`（不查看历史聊天）、不申请 `note.write`（不替学长写笔记）、不申请 `agent_memory`（不上报访问事件）。 |
| **可撤回** | `/api/auth/secondme/revoke` 撤销接口 + UI 一键按钮，本地 token 立即清除，对话能力即时下线。 |
| **输出标识** | 对话工作台顶部水印："本工作台中由 SecondMe 分身或兜底 LLM 生成的回复均为「**AI 助手代为表达**」，非学长学姐本人直接发言；所有学长资料来源于本人主动填写或本人授权的 SecondMe 分身调用。" |

合规依据：
- 《中华人民共和国个人信息保护法（PIPL）》第 13、14、17 条；
- 《中华人民共和国民法典》第 990-1010 条人格权益保护，第 1019 条肖像权（含 AI 合成）；
- 《生成式人工智能服务管理暂行办法》第 7 条训练数据合法性要求。

## 6. 后续计划

### 6.1 评审通过后短期（1-2 周）

1. 邀请 5 位剩余 mentor 完成 SecondMe 分身注册与训练，完成各自的 OAuth2 授权；
2. 将 `mentor_tokens.json` 文件存储迁移至 PostgreSQL + KMS 加密；
3. 实现 OAuth2 refresh token 自动续期；
4. 部署到内测域名 + HTTPS，注册 SecondMe 生产环境应用；
5. 实现 SecondMe 撤销 webhook 接收端（`/api/webhooks/secondme/revoked`）+ HMAC-SHA256 签名校验。

### 6.2 中期（1 个月）

1. 隐私级别（公开 / 握手后可见 / 仅本人确认后可见）后端对接：
   - 三档对应不同的 SecondMe `memory.read` 字段筛选策略；
   - 学长本人可随时调整级别；
2. 接入 SecondMe Key Memory 搜索接口，让分身能"召回"具体经验细节；
3. 雷达图匹配算法升级：从静态打分到基于 mentor 真实经验和 mentee 真实需求的语义匹配；
4. 真人引荐链路落地：分身对话结束后，可选向 mentor 本人发起 RE:FUDAN 真人会面邀请。

### 6.3 长期愿景

1. 形成"**经验先抵达**"的校园社交新范式：A2A 前哨对话成为常态；
2. 与复旦校友会、就业指导中心合作，扩展 mentor 池至 50+；
3. 沉淀对话场景下的"分身回答质量评分"反馈，反哺学长本人补充经验记忆。
